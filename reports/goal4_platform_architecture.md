# Selected offline VEK280 deployment architecture

The selected deployment uses a standalone Cortex-A72 supervisor in OCM and the existing PL detector. This is an offline design choice, not an observation of the disconnected physical unit. Installed board definition `xilinx.com:vek280:part0:1.2` selects `xcve2802-vsvh1760-2MP-e-S`. Actual Vivado 2025.2 catalog probe found `versal_cips:3.4`, `axi_noc:1.1` and `smartconnect:1.0` (`build/vek280_system/platform_probe.log`). AMD describes the A72/SD interfaces and three LPDDR4 systems in [UG1612 board features](https://docs.amd.com/r/en-US/ug1612-vek280-eval-bd/Board-Features), [Versal device](https://docs.amd.com/r/en-US/ug1612-vek280-eval-bd/Versal-Device), and [LPDDR4 memory](https://docs.amd.com/r/en-US/ug1612-vek280-eval-bd/LPDDR4-Component-Memory).

## Actual integrated platform

The concrete generated design selects the first LPDDR4 triplet using the installed `LPDDR4_Controller0_preset`: `ch0_lpddr4_trip1`, `ch1_lpddr4_trip1`, `lpddr4_clk1`. UART0 and SD1 addresses come from generated headers, never from a reference BSP default.

Cold loading reads one frozen metadata sector and 64 MiB arena from an explicitly selected reserved raw SD slot, with no SD writes. Metadata binds length/model/mask/threshold/extent. SD DMA bounces through aligned OCM; cache flush/invalidate and barriers surround transfer to the noncoherent shared arena. A one-byte hello and 64-byte ready identity wait for cold loading/configuration before full payload transmission.

The Windows host applies the existing document-only tokenizer/window policy and sends 64-byte headers plus uint 32 IDs[L], uint 32 types[L], uint 8 prefix masks[L]. Selected UART8N1 at 115200 baud is explicitly included in complete checking cost. The supervisor validates packet/document order and model identity, copies the arrays, flushes them, issues `dsb sy`, submits actual mailbox MMIO, waits for captured completion, verifies identities, sends a 64-byte response and acknowledges the result. No detector arithmetic executes on A72. Invalid packet, identity, polling-bound or engine errors terminate supervision and require explicit reset. Batches are sequential queue groups with no parallel speedup claim.

Actual selected BSP `xiltimer` uses configured 99999908 Hz. The supervisor timestamps immediately before mailbox submit through observed completion and emits elapsed nanoseconds in response bytes 56..63. This interval includes A72 submit/poll overhead and complete PL work; it excludes UART, copying and cache maintenance and is distinct from internal PL cycles. Timer calibration/runtime remain later physical inputs.
