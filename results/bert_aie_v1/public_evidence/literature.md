# BERT/AIE primary-source and implementation review

Verified 2026-10-15. Supporting source review only: no experiments, installs, training, protected-data reads, board access or shared handoff edits. Primary arXiv/publisher texts and author/vendor repositories were read through the web tool. Academic-search MCP is unavailable; direct primary-source verification was used. This supports architecture selection, without establishing novelty or target performance.

## Current AIE4ML constraints

[Author repository](https://github.com/cern-nextgen/aie4ml) redirects from dimdano/aie4ml, Apache-2.0. Current README requires **Vitis2026.1.1 and a valid AIE tools licence**; coordinator reports local2025.2. Cached older search text mentions2025.2, which does not prove current-main compatibility. Pin and inspect a compatible revision or qualify a focused port; do not silently assume2026.1.1.

[Support contract](https://github.com/cern-nextgen/aie4ml/blob/main/docs/support.md): static per-tensor power-of-two scales; dynamic MatMul rejects batched RHS; Add needs equal shape/type without broadcasting; LayerNorm int8, power-of-two last axis; softmax int8 in, uint8/Q8 or int16/Q15 out, last-axis length multiple of eight. Transpose covers last two axes. Slice/Split/Concat align to producer tiles. General BERT Reshape, embedding Gather, GELU and tanh are not advertised. Separate per-head 2-D MatMuls may lower attention, but must be proved; mask semantics need a qualified path. Graph boundary is PLIO; internal AIE→PL→AIE paths are explicitly unimplemented. Thus this is a component foundation, not automatic whole-BERT import. Existing optimization already ranks direct handovers and memory-tile traffic; fewer handovers alone is not an established new mechanism.

## Official target facts

[AMD VEK280 brief](https://www.amd.com/content/dam/amd/en/documents/products/adaptive-socs-and-fpgas/boards-kits/product-briefs/2487300-vek280-product-brief.pdf): VE2802 AIE-ML, 12GB 192-bit LPDDR4 and PCIe Gen4x16 connectivity. Connectivity does not supply a ready accelerator shell.

[AM020 array features](https://docs.amd.com/r/en-US/am020-versal-aie-ml/AIE-ML-Array-Features): 64KiB local memory/eight8KiB banks, 512KiB memory tiles, NoC DMA and PL clock-domain interfaces. [Functional overview](https://docs.amd.com/r/en-US/am020-versal-aie-ml/Functional-Overview): 256 i8xi8 MAC/tile/cycle, 128 BF16 MAC with FP32 accumulation, two256-bit loads/one store, 512-bit cascade; i8xi4 emulated at i8xi8 rate. FP32 multiplication is emulated and can differ from IEEE754. [Vendor DSP benchmark](https://docs.amd.com/r/2024.2-English/Vitis_Libraries/dsp/user_guide/L2/benchmark.html) uses xcve2802-vsvh1760-2MP-e-S at1.25GHz with64-bit PLIO/625MHz. This documents an example, not achieved SENTRY clocks or installed-platform identity; GAMA's128-bit/300MHz is another configuration.

[Generation comparison](https://docs.amd.com/r/en-US/am027-versal-aie-ml-v2/Comparison-of-AIE-Generations): original AIE has32KiB local RAM/no memory tiles; AIE-ML has64KiB and memory tiles; AIE-MLv2 changes compute, load/store and instructions. BF16 exponential acceleration from AIE-MLv2 cannot be assumed on VEK280. Local licence, XPFM, speed grade, banks and interfaces remain implementation checks.

## Bounded controls and falsifiable proposals

Decision stage: complete a competent baseline and isolate a mapping mechanism. Same checkpoint, numerics, threshold, masks/windows and host boundary for schedule comparisons. No literature speedup is a hard requirement.

1. Conventional control: tiled AIE GEMMs, competent PL nonlinear/rescale, banked buffers/double buffering, common QKV packing, resident/prefetched weights and reusable engines across four layers; actual embedding/head/document control included.
2. Residency/placement candidate: keep selected rescale/residual/normalization or attention row state near GEMMs; retile with memory tiles instead of crossing to PL. Match numerics and engine budgets where feasible. Discriminator: crossing bytes/stalls and complete-document first-result latency including transport. Falsify if less traffic fails to improve total cost, capacity/routing erases benefit, or output semantics fail the prospective contract. Generic residency/fusion is prior art.
3. Engine-sharing candidate: analytically select shared matrix pool, small specialized pools or hybrid; account for weight reload/layout/live buffers. Falsify if specialization only improves throughput while worsening batch-one/document cost, or cannot route/fit. CAT/SSR already establish hybrid sharing.
4. Optional precision/placement pairing: first compare mappings under same qualified numerics; only then add explicitly adapted integer nonlinear variants on matched mappings. Quality/decision-boundary evidence must independently qualify the variant. HCCS/I-BERT do not supply SENTRY security results.
